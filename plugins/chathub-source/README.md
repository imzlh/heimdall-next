# Microsoft ChatHub

渠道配置中的 `softThinking` 默认按 `auto` 工作，设为 `off`
可关闭。在渠道配置页面的“软思考”选项中修改，也可通过预设配置传入。

软思考识别 `extensions.raw.reasoning_effort` 和
`extensions.raw.reasoning.effort`，忽略大小写和首尾空格：

- `none` 不添加思考提示；`minimal`、`low` 强调直接回答和简短核验。
- `medium`（未指定时的默认值）检查当前目标、约束、证据和完成度。
- `high`
  增加内部任务拆解、事实与假设区分，以及工具成功、错误、缺失和截断结果的核验。
- `xhigh` 再检查关键假设、反例、依赖和边界情况。
- `max`
  再增加可行的独立一致性检查，区分已验证完成和仅尝试执行，避免重复规划或冗余工具调用。

这些等级只在既有请求中增强提示，不增加上游硬思考预算，也不要求输出内部思维链或为软思考额外发起请求。提示保留所需的回答和工具调用格式；实际推理深度仍由上游决定。

工具路由会校验完整调用批次；无效的路由结果最多修复一次，仍无效则返回错误。相互独立的调用可以同批返回；依赖前序结果的调用应等待结果后再继续。请求设置
`extensions.raw.parallel_tool_calls=false` 时，每批最多返回一个调用。

重建上下文时，工具结果共享 96,000
字符的正文预算，优先保留最近结果；较早的长结果压缩时保留首尾和截断标记，并保留调用标识、工具名称和错误状态。该预算仅约束工具结果正文，不是整段对话的总长度上限。

会话复用会检查历史是否兼容。模型、上游 `tone`
（回答引擎）、指导提示、工具定义或已有历史图像变化时重建；失败的会话会废弃，后续请求使用重建的上下文。图片重建只回放最近
10 张可内联的用户图像，不主动下载远程图片 URL；更早的图片不会全部重新上传。

未上传的远程图片、工具结果中的图片会标记为不可用；图片字节仍参与历史校验，防止修改截图后误用旧会话。

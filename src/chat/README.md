# Chat 服务与历史分支

`http/chat-routes.ts` 负责 HTTP / WebSocket 的输入校验、鉴权接入和传输；
`service.ts` 负责两种传输共用的会话命令、模型调用、工具循环和结果保存。
`runs.ts` 的会话锁覆盖生成、编辑、分支切换、复制、改名和删除。 工具通过
composition 注入，Chat 服务不识别搜索、记忆等具体插件名称。

`context.ts` 在命令执行时补全插件上下文：`conversationId` / `sessionId`
使用当前会话 ID，`traceId` 沿用调用者值或本次命令 ID，`purpose` 默认为
`chat`。工具后的模型请求使用独立 `:tool:N` 请求 ID；自动标题使用 `:title` 和
`chat.title` purpose，共享追踪 ID 与取消信号。上下文 metadata 进入 HIP 请求和
SourceContext，供路由亲和、请求日志及源插件读取；generation payload 的 metadata
保持为上游协议字段，宿主信息不会随之转发。源插件自行决定怎样
使用这些字段。工具执行收到 JSON 格式的 `requestId` / `metadata`，无需读取 HTTP
请求或凭证。原有插件 metadata 保留，标题请求不会污染 ChatHub 的热会话缓存。

历史由 `ChatStore` 保存为消息树。`parentId` 决定模型看到的前缀；SQLite 的
`active_message_id` 与 `selected_child_id` 保存当前路径及各子树的上次选择。
`branch_group_id` 是稳定的版本身份，删除中间节点并重接后续消息不会把不同轮次
误认为同一条消息的版本。编辑、重生成和续写通过写入参数 `variantOf`
加入原版本组， 原消息及其后续分支始终保留。

- 发送：在当前路径末尾追加用户消息，然后生成。
- 重生成：使用目标助手消息之前的前缀，新回复成为它的版本。
- 续写：模型输入包含目标助手正文，第一轮输出与原文合并成新版本；工具下一轮
  使用替换后的历史，避免重复发送原文。WebSocket 先发送原文，再发送新增 delta。
- 编辑：创建同角色的新版本。用户消息编辑后重新生成，助手消息编辑只保存正文。
- 复制会话：仅复制指定消息的祖先路径，分配新 ID，保留附件引用和会话设置。
- 删除：删除当前路径的一问一答并重接幸存节点。消息旁的版本导航保持原组身份，
  `conversation.branches` 提供所有幸存叶子的入口，包括不再共享前缀的路径。

所有消息批写、版本选择和对应更新时间在同一个存储事务提交。迁移旧平铺历史时
按每个会话的 `rowid` 顺序建立父子关系，不依赖可能重复或倒退的时钟。
失败和停止会保存已经生成的可见正文；没有新增正文的失败不会覆盖旧回复。

图片通过 `assets.ts` 解析本地引用；普通响应不携带存量 base64。
删除前只收集受影响的资产 ID，提交历史删除后回收已经没有任何分支引用的资产。
损坏的旧附件隔离保存，用户删除对应消息或会话时同时清除隔离内容。
